# 解析可靠性与正文检索改进

以 `8892304` 为代码基线，沿用 [索引性能优化与同输入验收 Flow](flows/index-performance/FLOW.md)。旧、新基准输入及旧生产发布指针保持不变，所有测量使用独立副本和新 store。性能任务及后代统一 12 GiB、禁 swap，串行运行，保留失败记录。

## 实现契约

1. 文件级解析错误保留源码和错误状态。工具启动、协议、存储、取消、超时和资源错误终止构建，旧发布指针保持不变。Ctags 可复现崩溃采用有界批次二分定位，失败输出不入库；Cscope 仍严格验证完整产物。
2. JS/TS 使用锁定版本 TypeScript 的纯语法 AST，覆盖泛型、嵌套作用域、方法和调用。保持单写入者、有界 worker 与稳定消费顺序，不建立项目级类型检查器。
3. Python 明确选择并验证 3.14 运行时。每文件缓存行布局，在 ast.parse 边界处理输入异常，其他异常继续传播。有界异步批次支持取消，严格核验每批文件结果。列坐标遵循现有 JavaScript UTF-16 契约，通过非 BMP 字符测试核验最终 UTF-8 字节证据。
4. 正文索引覆盖扫描纳入的全部文本，与符号解析状态分离。使用现有 SQLite 的整文件 FTS5，正文查询有独立模式和包含真实命中位置的证据。元数据查询不读 source blob。增删改名维护正文索引，旧快照继续可查。
5. 解析器、运行时及存储格式进入配置身份。格式变化重建，不做旧库就地迁移。原子发布、源码摘要和增量等价检查继续生效。

## 设计审议决策

独立规划代理指出批次错误扩散、协议错误被误判 partial、UTF-16/UTF-8 列差异、全文检索证据及 no-op 配置身份风险，纳入实现和测试。采用单一 TypeScript 语法引擎和每批 Python 进程，暂不引入常驻解析服务。保留现有坐标接口并修正 Python 转换，控制跨模块改动。Cscope 尚无已确认的输入级崩溃需要降级，本轮保留严格失败语义，避免把异常空关系当作成功。

## 验收

- 独立预期覆盖泛型、方法、重载、TSX、模板插值、嵌套函数、Python 3.14、非 BMP 字符和 CRLF。
- 单文件异常不影响批内其他文件，系统错误、损坏协议和消费者异常不被吞掉。取消后无残留后代，旧指针不变。
- 正文命中覆盖注释、函数体、Markdown、unsupported 和 partial 文件，片段包含命中，摘要与字节范围一致，删除内容不残留。
- 全量与连续增量比较完整文件状态、符号、父节点、关系、正文索引及 Cscope 正文，保留旧读者。
- 固定输入记录构建、查询、更新、覆盖、CPU、三种内存口径和体积。新旧符号提取能力变化采用独立语法预期评价，保留旧查询与调用验收，避免将旧解析遗漏固化成正确答案。
- 文档与结果提交后合并默认分支、推送并清理工作区。CLI 项目没有常驻实例，无需重启其他服务。
