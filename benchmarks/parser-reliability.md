# 0.4 解析可靠性与全文检索验收

CodeIndex 0.4 使用 TypeScript 语法 AST、CPython 3.14 和文件级故障隔离，并为全部纳入文本建立正文 FTS。CPython、VS Code、LLVM 的九次完整构建均成功，171,129 个文件的索引正文摘要与冻结输入一致。LLVM 的 Ctags 崩溃被定位到一个测试文件，其余文件继续完成构建。

产品版本固定为 `dec7a41`。完整记录在 [results/reliability](results/reliability)，运行与复验入口在 [reliability](reliability/README.md)。修复前记录保存在 [results/reliability-pre-review](results/reliability-pre-review)。

## 实现与错误边界

- JS/TS 采用锁定的 TypeScript 5.9.3 `createSourceFile`，提取泛型、嵌套声明、方法、箭头函数、JSX/TSX、导入和语法调用关系。独立名称索引保证精确声明进入候选池，再与全文候选合并。
- Python 使用 CPython 3.14.2，每文件缓存布局，有界异步解析批次。`ast.parse` 的语法和输入异常只影响当前文件，提取异常与协议错误终止构建。
- Ctags 仅对 `SIGSEGV` 采用有界二分，失败批次输出丢弃。单文件失败还需正常输入探针确认工具可用。拆分共享截止时间和最多 128 次额外尝试。启动失败、普通非零退出、取消、超时、存储和资源错误阻止发布。
- 坐标统一为 LF 行、UTF-16 列，写入证据时转换为原源码 UTF-8 字节。协议拒绝越界坐标，CR、CRLF、Unicode 行分隔符与非 BMP 字符有独立回归。
- `source_fts` 保存完整纳入文本，包括 unsupported 和 partial 文件。`--mode content` 使用 unicode61 短语语义，证据定位实际命中并核验冻结源码摘要。metadata-only 跳过源码 blob。
- 新格式为 `codeindex-index-0.4.0` / `codeindex-compact-2`，旧索引重新构建。删除最后一个 Python 输入后，更新按剩余语言决定运行时依赖。

运行契约见 [原生索引说明](../docs/native-index.md)，设计与验收约束见 [改进计划](../docs/parser-reliability-plan.md)。

## 输入与测量方法

沿用上一轮冻结的 CPython 3.14.0、VS Code 1.105.0、LLVM 21.1.0 输入与题集，作为已见回归集。输入以独立副本存放在 `.data/reliability/inputs`，新索引、更新副本和全量 oracle 均使用 `.data/reliability`。旧横评输入、原始记录及生产发布指针保持原位。

主机为 Ryzen 7 255、16 逻辑 CPU、约 19.32 GiB 内存，Node 24.13.1，Universal Ctags 5.9，Cscope 15.9。建库和查询沿用四 worker、预热文件缓存及三轮重复协议。所有被测进程及后代限制为 12 GiB、禁 swap，并串行执行。建库上限 1,800 秒，普通查询与更新上限 300 秒，完整等价上限 1,800 秒。

GNU time 最大 RSS、采样进程树 RSS 和 cgroup 峰值分别保留。cgroup 峰值包括页缓存，进程树 RSS 可能重复计算共享页。构建耗时覆盖源码冻结、解析、正文入库、原生索引、校验和发布。

正文验证逐文件读取 FTS body，核对全部 171,129 个 SHA-256。三个查询审计共验证 215 个返回片段的摘要、字节内容和 LF 起始行。正文证据同时保留实际命中的字节范围，预算截断时显式标记。

VS Code 的泛型函数 `disposeIfDisposable<T>` 及其 `isDisposable` 调用已恢复。`DisposableStore` 的完整定义曾被大量引用文档挤出 FTS 候选池，名称索引召回修复后，三轮符号题均为 8/8。

LLVM 的 `SmallVector` 命中了正确文件，但前十证据主要是构造函数与测试声明，目标类声明行未覆盖。四条复杂 C++ 调用题中，Cscope 返回的被调用者为空，属于保留的能力缺口。建库成功、文件命中和完整语义覆盖应分别判断。Ctags/Cscope 仍提供语法交叉引用，编译上下文、宏展开、函数指针及完整重载消歧属于当前能力边界。

## 增量、恢复与测试

| 项目 | no-op，秒 | 单文件增量，秒 | 全量 oracle，秒 | 完整等价检查，秒 |
| --- | ---: | ---: | ---: | ---: |
| CPython | 0.36 | 2.75 | 12.19 | 6.85 |
| VS Code | 0.39 | 2.67 | 12.46 | 9.71 |
| LLVM | 0.62 | 79.64 | 123.52 | 98.50 |

增量验收在各项目独立副本中增加一个 helper、一个调用 helper 的函数和唯一正文短语。检查新增符号、调用和正文可见，旧题命中保持，再与独立全量重建逐文件比较。比较范围包含文件身份和行布局、解析状态、完整正文、全部符号与父节点身份、SQL 关系、源码 blob、整份 Cscope 主库正文和附属索引。完成后恢复源码字节、Git revision、mtime 与原发布指针，确认新增探针消失。

Cscope 附属索引按实际格式比较所有有意义字段。oracle 与增量 store 使用等长路径，保证主库头部及 posting 字节偏移一致；校验时跳过 x86-64 结构填充和未使用的字典块空间。首次 LLVM 校验因直接展开巨大 Buffer 差异而耗尽 V8 堆，原记录保留。最终改用有界流式摘要，三个项目均通过严格复验。

Node 24.13.1 与 Node 22.23.2 各通过 122 项测试。Node 22 的首次命令被本机同名 `env` 脚本截走，未实际执行测试，该记录保留为无效验收；有效记录为 `checks/node22-verified.*`，使用 `/usr/bin/env` 和明确 Node 路径，并核对实际测试数量。

PageIndex 的独立 155 文件副本全量建库 1.12 秒，六个符号题与一个正文题全部命中，正文逐文件摘要和返回证据通过核验。

最终保全检查核对旧两组共 325,510 个输入文件及对应原始源码、Git 状态，新副本恢复后的 revision、mtime 和发布指针，以及旧 Linux 生产指针的既定 SHA-256。历史结果目录与基线一致。详细结果见 [最终验证](results/reliability/final-verification.json) 和 [汇总](results/reliability/summary.json)。

修复前的九次建库、早期集成测试及失败诊断均保留。最终产品构建与查询以 `dec7a41` 的记录为准，验收脚本补强另行保留复验记录。
